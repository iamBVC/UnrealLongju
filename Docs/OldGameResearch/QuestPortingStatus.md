# Quest porting status

This guide summarizes the current quest importer/runtime and its limits. See [QuestSystem](QuestSystem.md) for architecture, dispatch, persistence and import commands. The port implements selected Lua semantics and gameplay bindings, not an unrestricted Lua interpreter.

## Original-game model

Metin2 quests use `quest / state / when` declarations with Lua bodies and optional `with` guards. State and flags belong to each player. NPC, item, timer and named-target events select eligible triggers. Dialogue calls suspend execution until a player responds, then resume with their execution context.

Quest APIs depend on real game systems: recognizing a call name alone does not implement inventory transactions, dungeon ownership, server timers or other authoritative behavior.

## Conversion diagnostics

Import the intended authorized corpus with `MT2ImportQuests` and inspect `Saved/MT2QuestConversionReport.txt`. The report is regenerated by importing and identifies unconverted statements, failed gates and unsupported triggers. Importing writes generated quest Blueprints and shared table/manifest assets; review the Content submodule diff.

Diagnostics depend on the dataset and importer. A rejected conditional can conceal unsupported calls in its body. Successful conversion, a successful process exit or an empty diagnostic list is not proof of complete gameplay fidelity.

Unconverted nodes retain source locations. Some stop execution; others allow surrounding converted nodes to continue. Review complete triggers before enabling partially converted quests in production.

## Implemented language subset

- Expression-based arguments/conditions, arithmetic, supported math/string helpers, distinct nil/boolean values and Lua truthiness.
- Operand-preserving, short-circuit `and/or`; syntax checks do not execute gameplay reads.
- Literal/library tables and private mutable runtime tables. Aliases share runtime identity; generated Blueprint class defaults are not mutated.
- Dynamic constructors, supported indexed/named assignments, nil deletion and `table.insert`.
- While/repeat/numeric-for lowering and `ipairs` sequence iteration. Iterator state survives dialogue suspension and restores shadowed variables; traversal stops at the first missing integer key and has an execution budget.
- Supported inline table callbacks and runtime-built menus through `select_table`.
- Quest-local functions, parameter frames, returns and ordered result lists. Bare local declarations initialize to nil.
- Simultaneous assignments evaluate supported right-hand values before publishing destinations. Native final-call expansion and nil padding follow the supported Lua list rules.
- Resumable quest-function result destinations publish after frame unwinding restores parameters. Cancellation or failure does not publish a successful return.
- Supported `string.format`, case conversion, bounded `string.find` and `string.gsub` patterns. Concatenation does not reinterpret literal format tokens.

General closures, arbitrary first-class function values, unrestricted iterators, mixed resumable expression lists and full lexical/table-field target semantics are incomplete. Resumable calls in repeated loop conditions and constructors require particular care.

The value model uses FString; invalid UTF-8 transformations fail explicitly. Arbitrary Lua byte-string parity is not supported. Table depth/entry limits, iteration budgets and bounded string work are intentional runtime safeguards.

## Dispatch, dialogue and targets

- Triggers filter by event type, current state, optional VNUM and named event/target.
- Helper-backed `with` gates execute before a trigger claims an event or is offered as an NPC choice.
- NPC conversations hold a server-owned lease and revalidate player/NPC/range/lifetime across suspension.
- `say` resolves values when executed, preserving loop-row dialogue. Wait/select/input responses resume the owning context; closing the dialogue cancels it.
- Item-take events distinguish the receiving NPC from the offered item. The server captures/rechecks the offered inventory contents.
- Entity-backed target and NPC queries use live per-world character IDs, not template VNUMs. Named target dispatch and proximity events consume that identity.
- Quest letters, journal state, timers and target markers are separate runtime state. Owner-client presentation does not establish cross-map relevancy or full legacy UI fidelity.

Unresolved item/scroll/target trigger variants must have real dispatch sources and correctly resolved identities; parser acceptance alone is insufficient.

## Gameplay bindings

Implemented subsets include:

- Health/mana/death reads, resource aliases, flags, cooldown helpers and Unix-time `get_time/get_global_time`. The port-specific `game.get_time` uses world time.
- Inventory counts/ranges, item metadata, socket/attribute operations and the recognized atomic item-copy/material-consumption transaction.
- NPC purge, entity/proximity helpers and default NPC shop calls.
- Map/empire-village warp routing.
- Party flag operations on locally online members' own quest managers.
- Skill predicates, book-delay affects, alignment changes and grand-master learning.
- Authoritative fisherman rod refinement through the fishing system.

The item-copy transaction revalidates server inventory/NPC state and commits replacement plus material consumption together, or leaves inventory unchanged. Supported bonuses/socket copying and grid-fit rules still apply. Inventory snapshot matching compares contents; it does not provide persistent identity for otherwise identical instances. Other copy-call shapes and `item.select` require additional implementation.

Grand-master learning has gameplay logic, but quests using it can still depend on unsupported horse, confirmation or expression paths. Likewise, material-loop translation does not supply the separate cube UI/backend.

Quest flags are signed 32-bit, including stored timestamps; the 2038 limitation remains. `is_test_server()` returns false, so test-only branches are disabled.

## Remaining gameplay work

- Authoritative dungeon/instance ownership, unique mobs, regen, party instancing, instance warps and dungeon-wide timers.
- Dragon Soul qualification/refinement, pets, marriage, guild wars/buildings, forked-road events and remaining horse APIs.
- Cube, safebox/mall and unresolved quest/UI integration.
- Placeholder bindings such as dungeon/polymorph, marriage/engagement, wear/part queries. Review each binding's actual return behavior instead of assuming name registration means parity.
- Dialogue/broadcast ownership, cross-map entity identity/relevancy and persistence/reconnect behavior.

## Validation workflow

Run the `Metin2.Quests` automation group using the [project test workflow](../../README.md). Fixtures cover language values, loops/tables, function results, dialogue cancellation, resource reads, item transactions, NPC identity and supported gameplay APIs.

Import the intended corpus, inspect generated definitions and diagnostics, then exercise the affected quests on dedicated servers with real clients. Include dialogue suspension, item changes during menus, persistence, map travel and cooked assets. Unit tests and imports do not replace these playthroughs.
